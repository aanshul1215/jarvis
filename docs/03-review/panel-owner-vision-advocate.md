# Panel position: owner-vision-advocate (2026-10-02)

## Headline view on the reviewer's over-build concern
The concern is half right. The current design is over-built in infrastructure (three Windows accounts, ACL matrix, emailed hashes,
API workspaces and capital tiers, mutation gate, G4/G5 ladder, a live-satellite path with an expected effect of -$14 to -$18 a year,
live dollars at month 12-15). It is under-built in the thing the owner actually asked for: a co-pilot whose agents do visible,
useful, verified work, that scans, explains, remembers, and grows. The right correction is to move effort from plumbing to agent value,
not to shrink the agent team. The specialists' cuts are mostly correct; the places they risk hollowing JARVIS out are
(1) demoting the Reader and the ML heritage to "deferred" with nothing visible in their place, (2) making every agent attended with no scheduled output,
(3) hiding agent activity from the owner under the "exception-only" information diet, and (4) dropping any visible crypto.
My modifications target exactly those.

## Additions the specialists missed
1. **Agent Desk**: one dashboard tab and one memo block, "what each agent did this week", fed by S06-P8 memories, the report card and validator pass rates. It makes the agent team visible without adding spend.
2. **Weekly Opportunity Board**: code-ranked, factual list of what moved in the five asset classes, the watch list (8-K items, Form 4 clusters, z-scores) and the crypto shadow line, forward-scored and linked to the Idea Journal. Narrated as facts, never recommendations (S04-P5 policy). This is the owner's "scan for opportunities" without trading single names.
3. **`/whatif` mode of the Ledger Analyst**: counterfactual questions answered by code (Behaviour P&L, shadow variants, the dial b), so the co-pilot answers "what if I had held through March?" without inventing a story.
4. **Plan-usage budget table per role** (tokens per week, run count), review in P1a, with a pre-registered rule: if the plan limit trips twice in P1a, drop the scheduled Reader to every other week before touching Builder time.
5. **Owner Charter (one page)**: success is (a) after-tax result versus S0/S0-RM, (b) Behaviour P&L, (c) tested agents; and a written line that "benchmark runs, JARVIS monitors" is a successful outcome. Prevents the owner feeling misled (risk 1).
6. **Minimum lovable JARVIS by month 2-3**: first shadow email, Analyst memo, baseline import, and RECOMMEND-live S0, so the owner has something useful long before an executor exists.
7. **v1 post-mortem as a deliverable**: the leaked TSLA model written up in the Lab as the first Replication/Red-Team teaching case, honouring the owner's heritage.
